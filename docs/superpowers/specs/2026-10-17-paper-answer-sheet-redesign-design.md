# 갱지 답안지 리디자인 — 설계서

작성일: 2026-10-17
대상: `index.html` 전면 리디자인 (학생 화면 + 선생님 화면). `Code.js`는 필요한 최소 변경만.
참고 시안: `.superpowers/brainstorm/2139-1792206029/content/` 의 `direction-v2.html`(A안), `student-flow.html`, `teacher-view.html`

## 1. 의도와 이유

- 지금 화면은 칠판 헤더 + 파란 OMR 카드 + 이모지·그라데이션·색 배지가 가득해서 "AI가 만든 앱" 느낌이 나고 산만하다.
- 사용자(초등 교사)는 **실제 초등 단원평가 답안지**처럼 보이고, 더 **깔끔**하길 원한다. 기존 디자인은 갈아엎어도 된다.
- 문제는 종이 시험지로 따로 나가고, 이 앱에서는 **번호와 답 칸만** 입력한다. 화면에 문제 글은 없다.
- 기기: 학생은 **노트북과 태블릿**. 둘 다 잘 되도록 반응형 (휴대폰 폭에서도 깨지지 않을 것).
- 선생님은 채점할 때 **문항 하나를 반 전체에 걸쳐 쭉 매기는** 편이다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 학교에서 나눠주는 갱지 답안지(검은 표: 번호 | 답 | 배점·채점)를 화면으로 옮긴 느낌.
- 색은 검은 잉크와 선생님 빨간 펜 두 가지뿐. 빨간색은 "선생님이 쓴 것"에만 쓴다.
- 선생님 화면도 같은 결(같은 종이, 같은 표)로.
- 기존 기능(자동 채점, 서술형 수동 채점, 결과 공개 흐름, 정답 편집, 통계, 제출 초기화)은 모두 유지.

**비목표**
- 서버 채점 로직·시트 구조 변경. 문제 글 표시 기능 추가. 학년/반 입력 칸 추가(현재 데이터에 없음).

**실패 조건 (기능은 되더라도 실패로 보는 것)**
- 이모지 장식, 그라데이션, 둥근 카드에 그림자 깔린 SaaS 카드 느낌, 색 배지가 남아 있음.
- 빨간색이 버튼·경고 등 선생님 채점 이외 용도로 쓰여 "빨간 펜" 의미가 흐려짐.
- 태블릿에서 동그라미 버블이 손가락으로 누르기 작음(44px 미만 터치 영역).
- 입력한 글자를 손글씨 글꼴로 보여줘 선생님이 읽기 어려움.

## 3. 정해진 것 (사용자 결정)

- **방향 A: 갱지 답안지(표 형태)** — 사용자 선택.
- **답만 입력**, 문제 글 없음 — 사용자 결정.
- 노트북·태블릿 반응형 — 사용자 결정.
- 학생 화면 3단계(쓰는 중 → 내고 기다림 → 채점 결과), "참 잘했어요" 도장 — 시안 확인 후 "좋아".
- **OMR 색상 테마 5종 기능 제거** — 질문에 "좋아"로 답함.
- 선생님 화면 같은 결, 탭 3개(채점 / 결과 보기 / 정답과 설정) — "이렇게 가자".
- **채점 탭 첫 화면 = 문항별로 모아서** (사용자 채점 습관).

## 4. 시각 체계

**색 토큰** (`:root`에 정의, 인라인 색 하드코딩 금지)
| 이름 | 값 | 용도 |
|---|---|---|
| `--desk` | `#b9bfb3` | 페이지 바탕(교실 책상) |
| `--paper` | `#ebe6d6` | 갱지. 아주 옅은 점 질감(`radial-gradient`, 3px) |
| `--paper-shade` | `rgba(0,0,0,.05)` | 표 머리칸 |
| `--ink` | `#1f1f1d` | 모든 선·글자·마킹 |
| `--ink-soft` | `#3b3f37` | 보조 글자 |
| `--red-pen` | `#d6262b` | 선생님 채점 표시·점수·한 말씀·도장 **전용** |

- 다크 모드는 지원하지 않는다(종이 메타포; 내 결정). `body`에 명시적 배경색.
- 그림자는 종이 한 장 아래 아주 얕은 것(`0 1px 2px`) 하나만. 둥근 모서리는 버블(원)과 스위치만, 표·종이·버튼은 직각에 가깝게(0–2px).

**글꼴** (Google Fonts)
- 제목: **Gowun Batang 700** (명조, 시험지 제목).
- 본문·표·입력값: **Nanum Gothic 400/700/800** (인쇄체). 학생 입력 글자도 이것.
- 빨간 펜: **Nanum Pen Script** — ○ △ / 표시, 점수, 정답 표기, 한 말씀에만.
- Jua, Gowun Dodum 제거. 존재하지 않는 굵기로 가짜 볼드 만들지 않기.

**아이콘·이모지**: 쓰지 않는다. 필요하면 글자나 단순한 선 SVG.

## 5. 학생 화면

공통: 책상 바탕 위에 갱지 한 장(최대 폭 약 760px, 가운데). 종이 위쪽에 명조 제목 = `examTitle` 그대로(부제 칸은 만들지 않음 — 내 결정; 교사가 제목에 단원명을 함께 쓰면 됨).

**① 답 쓰는 중**
- 제목 아래 정보 표: `번호 [입력] | 이름 [입력]` (표 칸 안에 테두리 없는 입력, `<label>` 연결).
- 답 표: 열 = `번호 | 답 | 배점`.
  - 객관식/기호(ㄱ,ㄴ,ㄷ)/기호(가,나,다)/OX: 원형 버블(시각 지름 약 32–36px, 터치 영역 ≥44px). 숫자는 작게 인쇄된 듯. 누르면 `--ink`로 꽉 칠해짐(연필로 칠한 느낌, 짧은 채움 전환 ≤120ms, reduced-motion이면 즉시). 다시 누르면 지움. `<button>` 또는 radio로 구현, 키보드·포커스 링 필수.
  - 객관식은 기존처럼 6번 이상 번호를 쓸 수 있는 작은 "다른 번호" 입력을 유지(조용한 밑줄 입력).
  - 단답식: 밑줄 입력. 빈칸이 여러 개면 답 칸 안에 `(1) ___ (2) ___` 줄로 나눔.
  - 다빈칸 선택형: 답 칸 안에 `(1) ○○○○ / (2) ○○○○` 줄로 나눔.
  - 서술형: 답 칸이 넓은 여러 줄 입력(줄 노트처럼 가로줄은 선택, 내 판단).
- 맨 아래 검은 직사각 버튼 **"답안지 내기"**.
- 빈 칸이 있을 때 확인은 브라우저 `confirm` 대신 종이 위 인라인 안내(빈 문항 번호 나열 + "그래도 내기" / "다시 보기")로 (내 결정).

**② 내고 기다리는 중**
- 같은 답안지를 읽기 전용으로 흐리게(투명도 ~0.55) 보여주고, 아래 점선 상자: **"답안지를 냈어요. 선생님이 채점하시면 이 화면에 바로 나와요."**
- 멈춘 것처럼 보이지 않게 아주 작은 표시(예: 마지막 확인 시각 또는 천천히 깜빡이는 점 하나). 폴링 로직은 기존 그대로.
- **새로고침해도 기다리는 화면으로 복귀** (사용자 요청): 제출 성공 시 `localStorage`에 `{studentNumber, studentName, answers, examTitle, submittedAt}` 저장(모든 접근 try/catch). 페이지 로드 시 저장값이 있고 `examTitle`이 현재 시험과 같으며 12시간 이내면(내 결정) 답안지 대신 ② 화면을 바로 보여주고 폴링 시작. 결과(③)에서 "처음으로"를 누르면 삭제.
  - 기기를 돌려 쓰거나 선생님이 제출 기록을 지운 경우를 위해 ② 화면 아래에 조용한 링크 **"다른 학생이 새로 쓰기"**(저장값 삭제 후 빈 답안지)를 둔다(내 결정).
  - 같은 기기·같은 브라우저에서만 동작. 서버 변경 없음.

**③ 채점 결과** (`showScore`가 true일 때)
- 같은 답안지, 셋째 열 머리가 `채점`으로 바뀌고 빨간 펜 표시: 맞음 `○`, 부분 `△`+얻은 점수, 틀림 `/` (빗금).
- `showCorrectAnswers`이면 틀린/부분 문항 답 옆에 빨간 펜으로 `→ 정답`.
- 오른쪽 위에 빨간 동그라미 친 총점(손글씨, 살짝 기울임).
- `teacherComment`가 있으면 표 아래 빨간 손글씨 한 줄.
- **만점이면 "참 잘했어요" 빨간 도장**(SVG, 이중 원, 기울임)이 한 번 찍히는 모션(살짝 크게 → 제자리, 약 300ms). canvas-confetti 제거. 이것이 화면에서 유일한 큰 연출.
- `showScore`가 false: 표시 없이 답안지 + "선생님이 채점을 마쳤어요." + 한 말씀.
- 아래 조용한 버튼 "처음으로".

## 6. 선생님 화면

**맨 위 줄**(책상 위, 종이 밖): 시험 제목(명조) · `제출 N명 · 채점 대기 M명` · **"학생에게 결과 보여주기"** 스위치(검은 잉크 스위치 + 켜짐/꺼짐 글자) · "학생 화면" 버튼.
- "채점 대기" = `isCompleted`가 false인 제출 수.

**탭 3개** (종이 파일철 인덱스 탭 모양): **채점 / 결과 보기 / 정답과 설정**. 첫 탭 = 채점.

**채점 탭** — 하위 보기 전환: **"문항별로 모아서"(기본)** / "학생별로".
- *문항별로 모아서*: 위에 문항 선택(번호 칸이 가로로 늘어선 표 머리 같은 선택기; 서술형과 보류가 남은 문항을 앞에/표시). 선택한 문항의 `번호·유형·배점·채점 기준(rawAnswerStr)`과 "M명 남음". 아래 표: `학생(번호 이름) | 답 | 채점`.
- *학생별로*: 왼쪽 명렬표(번호 | 이름 | 점수 또는 "대기"), 고르면 오른쪽에 그 학생 답안지 표: `번호 | 학생 답 | 정답 | 채점`. 아래 빨간 밑줄 한 말씀 입력, 버튼 "이전 학생" / **"채점 끝, 다음 학생"**(= 코멘트 저장 + `forceComplete: true`).
  - **보류가 남아 있을 때 "채점 끝"** (사용자 결정 2-나): 확인창 대신 버튼 자리에 인라인 안내 "아직 안 매긴 서술형이 있어요(4번). 완료하면 0점으로 보여요." + 버튼 두 개 **"한 말씀만 저장"**(코멘트만, `forceComplete`는 그 행의 현재 `isCompleted` 값을 그대로 전송 → 완료 상태 불변 (R11)) / **"그래도 완료"**(`forceComplete: true`). 둘 다 다음 학생으로 넘어감.
- **완료(공개 대상) 처리는 오직 "채점 끝"에서만** (사용자 결정 1-나): 문항별·학생별 보기의 ○△/ 채점 클릭은 행의 완료 상태를 **바꾸지 않는다**. 즉 `updateStudentQuestionGrade`에 `forceComplete: <그 행의 현재 isCompleted>`를 보낸다. 마지막 보류를 매겨도 자동 완료·자동 공개되지 않으며, 이미 완료된 학생을 다시 매겨도 완료가 풀리지 않는다. (서버 변경 없음. 제출 시 서술형이 없어 자동 완료된 행은 그대로 완료 유지.)
  - 그래서 "채점 대기 M명"과 명렬표의 "대기"는 `isCompleted` 기준이고, 문항별 보기의 "M명 남음"은 그 문항이 `보류`인 학생 수 기준이다. 문항별 보기에서 모든 보류를 매긴 뒤에는 "학생별로 가서 한 말씀을 쓰고 채점 끝을 눌러야 공개돼요" 한 줄 안내를 띄운다(내 결정).
- 채점 칸 공통: `○ △ [점수] /` 네모 칸. 선택된 것은 빨간 바탕. ○=만점, /=0점, △ 누르면 점수 칸에 포커스(기본값 배점의 절반), 점수 입력 후 Enter/blur로 저장. 교사가 덮어쓸 수 있음.
- "자동" 표시: 자동/수동 여부가 데이터에 기록되지 않으므로 행별 "자동" 표시는 하지 않고, 서술형이 아닌 문항의 머리에만 "자동 채점 문항"이라고 적는다(내 결정, 서버 변경 없음).
- **채점할 때 전체 새로고침·재렌더 금지**: `updateStudentQuestionGrade` 응답의 `newTotalScore`, `isCompleted`로 로컬 데이터와 해당 행만 갱신해 스크롤·포커스를 유지. 실패 시 원래 표시로 되돌리고 안내.
- `prompt()` / `alert()` / `confirm()` 사용 금지(제출 기록 초기화처럼 되돌릴 수 없는 동작만 인라인 2단계 확인).

**결과 보기 탭**
- 문항별 오답 표: `번호 | 틀린 학생(검은 막대 + N명 (x%)) | 가장 많이 쓴 오답`. 서술형 제외(기존과 같음). 막대 색은 잉크 하나.
- 아래 제출 명렬표(기존 요약표): 시간 | 번호 | 이름 | 총점 | 상태 | 문항별 요약. 가로 스크롤 감싸기.
- 맨 아래 "제출 기록 모두 지우기"(인라인 2단계 확인).

**정답과 설정 탭** (시안 없음, 같은 결로 구성)
- "정답표" 한 장: 기존 편집 표와 같은 열(번호 | 유형 | 칸 수(자동) | 정답 | 배점 | 부분점수 | 삭제), 검은 표 스타일. 입력 규칙 안내(쉼표=빈칸, 슬래시=유사 정답)는 표 위 짧은 두 줄.
- 설정: 시험 제목, 선생님 비밀번호, 스위치 4개(점수·정오 보여주기 / 정답 보여주기 / 띄어쓰기 무시 / 다시 내기 허용). 문구는 짧은 평서문.
- 저장 버튼 하나 **"저장"**, 결과는 토스트 "저장했어요".
- 테마 선택 UI 제거.

**공통 안내 방식**: 화면 아래쪽 작은 종이 쪽지 같은 토스트(잉크 글자, 약 2.5초). 오류는 무엇이 잘못됐고 어떻게 하면 되는지 한 문장.

**비밀번호 모달**: 갱지 쪽지 모양, "선생님 비밀번호" 입력 + 취소/들어가기. 오류는 모달 안 인라인 문구.

## 7. 반응형

- 기준 폭: 태블릿 세로(768), 태블릿 가로·노트북(1024–1440). 360px에서도 가로 스크롤 없이 동작.
- 학생 답 표: 좁은 폭에서 `배점/채점` 열은 좁게 유지하고 버블이 답 칸 안에서 줄바꿈.
- 선생님 학생별 보기: 900px 미만에서 명렬표가 위(가로 스크롤 또는 선택 상자)로 올라감.
- 넓은 표는 모두 `overflow-x: auto` 감싸기.

## 8. 접근성 품질 바닥

- 모든 클릭 요소는 `button`/`input`/`label`. 버블은 radio 그룹 또는 `aria-pressed` 버튼.
- `:focus-visible` 링(잉크색 2px + 오프셋)을 모든 입력·버튼·스위치에.
- `prefers-reduced-motion`이면 도장 모션·채움 전환 없음.
- 대비: 잉크/갱지 충분. 빨간 펜 `#d6262b` on `#ebe6d6`는 큰 손글씨 크기에서만 사용.
- 글자 사이를 공백으로 띄우는 표기 금지(스크린리더).

## 9. `Code.js` 영향

- `index.html`의 `google.script.run` 호출 이름·인자는 그대로 유지하는 것이 원칙.
- `omrTheme`: UI에서 제거. 서버의 설정 키는 **남겨둠**(기존 시트 호환, 내 결정). `saveTeacherConfig`로 보낼 때는 기존 값 그대로 전달하거나 `'blue'` 고정.
- 서버 메시지 문구 정리 권장(이모지·과장 제거, 예: 저장 성공 메시지). 토스트로 노출되므로.
- (R17) `remapSubmissionsToQuestions_`: 정답과 설정 저장으로 문항이 바뀌어도 각 행의 완료 값은 **이전 값 그대로** 둔다(예전 `wasCompleted || !hasPending` → `wasCompleted`). 완료는 '채점 끝'에서만(1-나).
- (R18) 클라이언트가 부르지 않는 서버 함수는 이름 끝에 `_`를 붙여 `google.script.run`에서 숨긴다(예: `getSettingsMap_`는 비밀번호를 돌려주므로). 공개 함수는 `doGet`, `include`와 클라이언트가 부르는 8개 RPC뿐.
- 그 외 로직 변경 없음.

## 10. 빌더에게 맡기는 것

- 정확한 간격·크기 수치, 탭 모양 세부, 토스트 위치.
- 문항 선택기의 구체 형태(가로 번호 칸 vs 드롭다운), 학생별 보기의 좁은 화면 처리 방식.
- 서술형 칸에 가로줄을 넣을지.
- 갱지 질감을 CSS로 할지 작은 이미지로 할지(이미지가 필요하면 Codex 이미지 생성 사용 가능 — 사용자 허락함). 기본은 CSS.
- CSS 구조(클래스 체계). 인라인 스타일은 최소화.

## 11. 검증

- 스텁(`google.script.run` 가짜 응답)으로 로컬 미리보기를 만들어 학생 3단계·선생님 3탭을 768/1024/1440/390 폭에서 캡처해 확인.
- 이후 `clasp push`로 테스트 배포에서 실제 제출 → 채점 → 공개 흐름을 수동 확인.
